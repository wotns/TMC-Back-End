## 👩‍💻 내 기여

### 상환 시뮬레이션 엔진 설계
- 원리금균등·원금균등·만기일시상환 방식별 계산 로직을 독립적으로 분리 설계
- 대출 금액·금리·상환 기간 기반 월 상환금·총 상환액 산출 로직 구현
- 중도상환 발생 시 수수료와 잔여 원금 감소를 반영한 시뮬레이션 흐름 구성
- 상환 방식·전략별 파생 결과 데이터를 생성·저장하는 데이터 처리 로직 설계

### 성능 최적화
- 상환 전략 계산 결과 캐싱 구조 설계(MySQL 저장 + Redis 캐싱 병행 방식)

### 시각화 데이터 가공
- 결과 데이터를 전략별·월별 비교 가능한 형태로 가공하여 시각화 및 추천 화면에 활용

## 🔥 트러블슈팅

### 1. 상환 플랜 계산 알고리즘 개선

**문제**
초기 시뮬레이션은 단일 계산 방식으로 구성되어 상환 방식 간 차이를 충분히 반영하지 못했고, 중도상환 수수료 등 실제 금융권 조건이 누락되어 신뢰도가 낮았음

**해결**
- 대출을 금액이 아닌 상환 방식 중심의 계산 도메인으로 재정의
- 상환 방식별 월별 계산 흐름이 다르다는 점에 착안하여 계산 로직을 독립적으로 분리 설계
- 중도상환 발생 시 수수료와 잔여 원금 감소를 반영하도록 시뮬레이션 흐름 구성

**결과**
실제 금융 상품 흐름과 유사한 월별 상환 스케줄 제공, 사용자에게 현실적인 상환 기간·총이자·납입금액 안내 가능

---

### 2. 상환 전략 계산 결과 비저장으로 인한 성능 저하 해결

**문제**
상환 전략을 사용자 접속 또는 화면 진입 시마다 새로 계산하는 구조로 인해 동일한 조건에서도 반복 연산이 발생하고 응답 속도가 저하됨

**해결**
- 상환 전략 계산 결과를 MySQL에 JSON 형태로 저장하여 이력 관리 가능하도록 설계
- Redis 캐싱을 병행하여 동일 조건 요청 시 즉시 결과 반환
- 전략 변경이나 대출 정보 수정 시에만 재계산되도록 흐름 제어

**결과**
- API 처리량 약 **4배** 개선
- 거래 데이터 비교 횟수 약 **70%** 감소
- 상환 시뮬레이션 화면 응답 속도 체감 개선
